GREF FarmWork
온실 운영 통합 관리 및 데이터 수집 플랫폼
GREF 산하 3개 지점(부산LAB, 진주HUB, 하동)에서 운영 중인 인력·작업·생육 통합 관리 시스템. 일상의 운영을 디지털화하는 동시에, 축적되는 작업 데이터를 향후 재배 AI 학습 자산으로 활용하는 것이 본 프로젝트의 우선 목적.
01 — 추진 배경
농업 데이터화의 구조적 공백
기존 농업 IT 시스템의 데이터 수집 범위는 크게 두 영역에 집중. 환경 센서 데이터(온도·습도·CO₂ 등)와 수확량 집계 데이터. 두 영역 사이에 위치한 작업 데이터 — 누가, 언제, 어떤 농작업을, 얼마나 수행했는가 — 는 대부분의 시스템에서 누락되거나 비정형으로만 기록됨.
작물 생육은 환경 변수와 작업 변수의 복합 결과물. 예를 들어 적엽 작업은 작물의 증산량을 직접 변화시키며, 이는 온실 내부 환경에 영향을 주고, 다시 다음 단계 생육에 작용. 작업 데이터의 부재는 생육 결과의 인과 분석을 불가능하게 함.
GREF FarmWork는 이 누락된 작업 데이터 영역을 체계적으로 수집·정형화하기 위해 개발됨.
02 — 시스템 구성
작업자 모바일 + 관리자 웹의 통합 PWA
구분내용
작업자 인터페이스QR 기반 출퇴근, 작업 기록, 생육 조사 입력, 이상 신고·호출
관리자 인터페이스작업 지시, 인력 운용, 근태·휴가 관리, 전체 현황 모니터링
데이터 저장모든 작업 기록은 작물·구역·시점·담당자 메타데이터와 결합되어 저장
권한 체계작업자, 재배팀장, 관리팀, 총괄, 마스터 5단계. 지점별 데이터 격리 적용
기술 기반PWA(Progressive Web App)로 별도 앱 설치 불필요
인력·작업·근태 관리 기능 자체로도 운영상 가치를 가지나, 본 프로젝트의 우선 목적은 이 기능들을 통해 자연스럽게 축적되는 작업 데이터의 수집·정형화에 있음.
03 — 차별점
3-1. 작업 데이터 완결성
환경 데이터·수확량 데이터에 더해 작업 데이터까지 포함한 통합 데이터셋 구축. 작업자가 별도 보고서를 작성하지 않으며, 평소 업무 흐름이 그대로 데이터 원천이 되는 구조. 기록 부담으로 인한 작업 효율 저하 없음.
3-2. 다지점 동시 운영 검증
3개 지점에서 단일 시스템으로 동시 운영 중. 지점 간 데이터 격리, 권한 분리, 통합 관제 구조가 실제 운영 환경에서 검증됨. 외부 농가로의 확장 시 필요한 다지점 운영 기반이 이미 확보된 상태.
3-3. 권한·보안 체계 정비
5단계 권한 체계 및 데이터베이스 수준의 행 단위 보안(RLS) 적용 완료(2026년 4월). 지점 간 데이터 격리, 역할별 접근 제한, 감사 추적 기반이 갖춰짐.
04 — 데이터 활용 방향
두 가지 AI 모델의 학습 데이터 공급
축적된 데이터는 두 가지 방향의 AI 모델 학습에 활용 예정.
모델설명
재배 AI작업·작물·환경 변수의 인과관계 학습. 작물 상태에 따른 최적 농작업 시점·종류·강도 제안. 사람의 경험에 의존하던 농법 의사결정을 데이터 기반으로 전환
인력 배치 AI (향후 도입)작업자별 작업 속도·정확도·학습 곡선 데이터를 기반으로 일별 최적 인력 배치 제안. 같은 인력 규모에서 작업 처리량 증대 및 신규 작업자 학습 기간 단축 기대
두 모델 모두 동일한 데이터 플랫폼 위에서 학습됨. 별도 데이터 수집 인프라 구축 비용 없음.
05 — 확장 가능성
외부 농가 보급을 통한 데이터 자산 다변화
단일 농장 데이터만으로는 AI 모델의 일반화에 한계. 작물 종류, 기후 조건, 운영 방식이 상이한 다수 농장의 데이터 확보가 모델 정확도 향상의 핵심 조건.
GREF FarmWork를 외부 농가에 보급하는 경우, 도입 농가는 즉시 운영 가능한 농장 관리 도구 확보, GREF는 다양한 환경의 학습 데이터 확보. 양방향 가치 교환 구조 성립 가능.
이 구조가 정착될 경우, GREF는 자체 온실 운영을 넘어 농업 데이터 인프라 보유 기업으로의 포지셔닝 전환 가능.
