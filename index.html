⬜ 01

Priva Read 파이프라인 구축

필수 +

무엇을 하는가

왜 하는가

AI가 학습하려면 데이터가 필요합니다. 현재는 사람이 수동으로 주 1회 기록하고 있으며, 자동 수집 없이는 AI 개발 자체가 불가능합니다.

어떻게 하는가

⬜ 02

필수 +

무엇을 하는가

센서 고장이나 통신 장애로 빠진 데이터를 자동 복구하고, VPD(포차), GDD(생육도일), DLI(일적산광량) 등 핵심 지표를 실시간 계산합니다.

왜 하는가

센서는 반드시 고장납니다. 빠진 데이터를 방치하면 AI가 엉뚱한 패턴을 학습합니다. 또한 식물은 '오늘의 온도'가 아니라 '심은 날부터 누적된 온도(GDD)'에 반응하므로 파생변수가 필수입니다.

어떻게 하는가

선형 보간과 이동평균으로 결측치를 복원하고, Python 모듈로 파생변수를 자동 계산합니다.

산출물

결측 없는 깨끗한 데이터 + VPD / GDD / DLI / DIF / RTR 자동 산출 모듈

용어 설명

이 프로젝트에서 사용하는 전문 용어를 일반인도 이해할 수 있도록 정리했습니다. 본문에서 점선 밑줄이 있는 단어에 마우스를 올리면 설명이 표시됩니다.

환경 제어 관련
VPDVapor Pressure Deficit, 포차
공기가 수분을 더 머금을 수 있는 여유. 높으면 건조해서 식물이 수분을 빨리 잃고, 낮으면 습해서 곰팡이가 생기기 쉽습니다. 온실에서는 0.8~1.2 kPa가 적당합니다.
GDDGrowing Degree Days, 생육도일
식물이 자라는 데 필요한 온도를 날마다 모은 누적값. "심은 날부터 오늘까지 받은 따뜻함의 총합"으로, 식물의 생장 단계를 예측하는 데 씁니다.
DLIDaily Light Integral, 일적산광량
하루 동안 식물이 받은 빛의 총량. 잠깐 강한 빛보다 하루 전체 광량이 중요하며, 토마토는 보통 DLI 15~25 mol/m²/day가 필요합니다.
DIF주야간 온도차
낮 온도와 밤 온도의 차이. DIF가 크면 줄기가 길어지고, 작거나 마이너스면 줄기가 짧아집니다. 식물 키 조절에 활용합니다.
RTRRadiation-Temperature Ratio, 광온도비율
빛의 양 대비 온도의 비율. 빛이 적은 날 온도만 높으면 식물이 웃자라므로, 이 비율을 맞춰 온도를 조절합니다.
MPCModel Predictive Control, 모델예측제어
미래를 예측하면서 최적의 제어를 찾는 방법. 내비게이션이 목적지까지의 경로를 계속 재계산하는 것처럼, 온실 환경의 미래를 예측하며 난방·환기 등을 조절합니다.
PARPhotosynthetically Active Radiation, 광합성유효복사
식물이 광합성에 실제로 쓸 수 있는 빛. 전체 햇빛 중 400~700nm 파장만 해당합니다.
ECElectrical Conductivity, 전기전도도
양액(비료 섞은 물)의 농도를 나타내는 값. 높으면 비료가 진하고, 낮으면 묽습니다.
Priva
네덜란드의 온실 환경 제어 시스템 회사. 온도·습도·관수 등을 자동으로 관리하는 장비와 소프트웨어를 만듭니다. 국내 대규모 온실에서 많이 사용합니다.
양액Nutrient Solution
식물에 필요한 비료 성분을 물에 녹인 용액. 수경재배에서는 흙 대신 양액으로 영양분을 공급합니다.
pH수소이온농도
용액의 산성·알칼리성 정도. 0~14 범위로, 7이 중성. 양액의 pH가 맞지 않으면 식물이 영양분을 흡수하지 못합니다. 토마토는 pH 5.5~6.5가 적당합니다.
CO₂ 시비이산화탄소 공급
온실에 이산화탄소를 인위적으로 넣어주는 것. 광합성 원료이므로 CO₂ 농도를 높이면 식물이 더 빨리 자랍니다. 보통 800~1200ppm으로 관리합니다.
관수Irrigation, 물주기
식물에 물을 공급하는 것. 온실에서는 타이머나 센서에 따라 자동으로 관수합니다. 점적 관수(드립)가 일반적입니다.
배액Drain
양액을 준 뒤 식물이 흡수하지 못하고 빠져나온 물. 배액의 EC와 pH를 측정하면 식물이 영양분을 얼마나 흡수했는지 알 수 있습니다.
결측치 보간Missing Value Imputation
센서 오류 등으로 빠진 데이터를 앞뒤 값으로 채워 넣는 작업. 데이터에 구멍이 있으면 AI가 학습할 수 없으므로 전처리 단계에서 필수입니다.

센서가 시간이 지나면서 점점 정확도가 떨어지는 현상. 정기적으로 교정(캘리브레이션)하지 않으면 잘못된 데이터가 AI에 입력됩니다.
적응형 제어Adaptive Control
상황에 따라 제어 주기를 바꾸는 방식. 예: 평소엔 30분마다 제어하다가, 고온 위험 시 10분마다 더 자주 제어하는 것.
천창Roof Vent, 환기창
온실 지붕에 있는 열리는 창문. 열면 뜨거운 공기가 빠져나가고 외부 공기가 유입되어 온도와 습도를 조절합니다.
스크린Energy Screen
온실 내부에 설치하는 커튼 같은 보온·차광 장치. 밤에 닫으면 열 손실을 줄이고, 한낮에 닫으면 과도한 햇빛을 차단합니다.
ppmParts Per Million, 백만분율
농도를 나타내는 단위. 100만 개 중 몇 개인지를 뜻합니다. 온실 CO₂ 농도(예: 800ppm)나 양액 농도 등에 사용합니다.
AI / 머신러닝 관련
RLReinforcement Learning, 강화학습
시행착오를 통해 스스로 학습하는 AI 방식. 게임에서 점수를 높이려고 반복 플레이하듯, AI가 온실을 제어하면서 "순수익이 높아지는 방향"으로 점점 똑똑해집니다.
R²R-squared, 결정계수
모델이 데이터를 얼마나 잘 설명하는지를 0~1로 나타낸 값. 0.9면 "90%를 설명한다"는 뜻으로, 높을수록 예측이 정확합니다.
MAEMean Absolute Error, 평균절대오차
예측값이 실제값과 평균적으로 얼마나 차이나는지. MAE가 0.91cm이면 "보통 1cm 이내로 맞힌다"는 뜻입니다.
RMSERoot Mean Squared Error, 평균제곱근오차
MAE와 비슷하지만 큰 오차에 더 민감한 지표. 크게 틀린 예측이 있으면 RMSE가 확 올라갑니다.
Random Forest랜덤 포레스트
여러 개의 결정 트리(질문을 반복해서 답을 찾는 나무 구조)를 만든 뒤 다수결로 결과를 내는 AI 기법. 안정적이고 설명하기 쉬워 첫 번째 테스트에 많이 씁니다.
LightGBMLight Gradient Boosting Machine
마이크로소프트가 만든 빠르고 정확한 예측 모델. 나무를 하나씩 추가하면서 이전 나무의 실수를 교정하는 방식으로 학습합니다.
YOLOv8You Only Look Once v8
사진 한 장을 한 번만 봐도 물체의 위치와 종류를 찾아내는 AI. 온실에서는 과일이나 병해충을 실시간으로 찾는 데 씁니다.
SAMSegment Anything Model
Meta가 만든 이미지 분할 AI. 사진에서 잎, 과일, 줄기를 각각 따로 잘라내어 면적이나 크기를 정밀하게 측정할 수 있습니다.
CLIPContrastive Language-Image Pre-Training
OpenAI가 만든 AI로, 이미지와 텍스트를 함께 이해합니다. "잿빛곰팡이 걸린 잎"이라고 글로 설명하면 해당 이미지를 찾아낼 수 있습니다.
ProphetMeta 시계열 예측 라이브러리
Meta(페이스북)가 만든 시계열 예측 도구. 가격이나 수확량처럼 시간에 따라 변하는 데이터의 패턴(추세, 계절성)을 자동으로 찾아 미래를 예측합니다.
LLMLarge Language Model, 대규모 언어 모델
ChatGPT, Claude 같은 AI. 이 프로젝트에서는 AI가 계산한 숫자를 재배사가 이해하기 쉬운 말로 바꿔주는 번역 역할을 합니다.
DeePCData-Enabled Predictive Control
시스템의 수학적 모델 없이, 과거 데이터만으로 최적의 제어를 찾는 방법. "이전에 이렇게 했더니 잘 됐으니 다음에도 비슷하게" 하는 방식입니다.
Concept Drift개념 드리프트
시간이 지나면서 데이터의 패턴이 바뀌는 현상. 여름에 학습한 AI가 겨울에는 잘 못 맞히는 것처럼, 환경이 변하면 AI도 다시 학습해야 합니다.
Sim-to-Real시뮬레이션 → 현실 전이
가상 환경(시뮬레이터)에서 먼저 AI를 훈련시킨 뒤, 실제 온실에 적용하는 방법. 실제 온실에서 시행착오를 겪는 비용과 위험을 줄입니다.
Shadow Mode섀도우 모드
AI가 제어 명령을 실제로 내리지 않고, "내가 이렇게 했을 것이다"만 기록하는 모드. 실제 제어는 사람이 하면서 AI의 판단력을 검증합니다.
PPOProximal Policy Optimization
강화학습에서 많이 쓰는 학습 알고리즘. AI가 너무 급격하게 행동을 바꾸지 않도록 조금씩 개선하면서 안정적으로 학습합니다.
CNNConvolutional Neural Network, 합성곱 신경망
이미지를 인식하는 데 특화된 AI 구조. 사진에서 가장자리, 색상, 패턴 등을 자동으로 추출하여 "이것은 병해다" 같은 판단을 내립니다.
전이학습Transfer Learning
다른 분야에서 미리 학습된 AI를 우리 분야에 가져와서 재학습시키는 방법. 처음부터 학습하는 것보다 훨씬 적은 데이터로도 좋은 성능을 낼 수 있습니다.
제로샷Zero-shot
한 번도 본 적 없는 종류의 데이터도 분류할 수 있는 AI 능력. 예: "흰가루병" 사진을 학습한 적 없어도 텍스트 설명만으로 해당 이미지를 찾아냄.
앙상블Ensemble
여러 AI 모델의 예측을 합쳐서 더 정확한 결과를 내는 방법. 여러 전문가의 의견을 모아 결정하는 것과 비슷합니다. Prophet + LightGBM 조합이 예시입니다.
SHAPSHapley Additive exPlanations
AI가 왜 그런 예측을 했는지 설명해주는 도구. "온도가 높아서 생장이 빨라질 것이다"처럼 각 변수의 기여도를 수치로 보여줍니다.
피처 엔지니어링Feature Engineering
AI에 넣을 입력 데이터를 가공하는 작업. 예: 온도 데이터에서 "3일 이동평균 온도"나 "전주 대비 변화량" 같은 새 변수를 만드는 것.
TimesFMTime-series Foundation Model
Google이 만든 대규모 시계열 예측 AI. 별도 학습 없이도 다양한 시계열 데이터를 예측할 수 있어, 실험적으로 테스트합니다.
ViTVision Transformer
이미지를 작은 조각(패치)으로 나눠서 처리하는 최신 AI 구조. 기존 CNN보다 큰 이미지를 더 잘 이해합니다. SAM, CLIP 등에 사용됩니다.
과적합Overfitting
AI가 학습 데이터만 너무 잘 외우고, 새로운 데이터에는 잘 못 맞히는 현상. 시험 문제를 달달 외웠지만 응용 문제를 못 푸는 것과 같습니다.
라벨링Labeling / Annotation
AI를 학습시키기 위해 사진에 "이것은 잿빛곰팡이" 같은 정답을 표시하는 작업. 사람이 수작업으로 하므로 비용과 시간이 많이 듭니다.
MAPEMean Absolute Percentage Error, 평균절대백분율오차
예측 오차를 퍼센트로 나타낸 값. MAPE 5%면 "평균적으로 5%만큼 차이난다"는 뜻. 직관적이라서 비전문가에게도 설명하기 쉽습니다.
작물 재배 관련
LAILeaf Area Index, 엽면적지수
온실 바닥 면적 대비 잎의 총 면적. LAI 3이면 바닥 1m²에 잎이 3m² 만큼 있다는 뜻입니다. 광합성 능력의 척도입니다.
TOMGRO
미국 플로리다 대학에서 만든 토마토 전용 생육 예측 모델. 온도·빛·CO₂를 넣으면 토마토가 얼마나 자라고 열매가 얼마나 열릴지 예측합니다.
GreenLight
네덜란드 바게닝언 대학이 만든 온실 시뮬레이터. 온실 기후(온도·습도) + 에너지 비용 + 작물 생장을 한꺼번에 계산할 수 있는 통합 모델입니다.
Ground Truth정답 데이터
실제로 일어난 결과 데이터. 수확량, 품질 등급, 경매 가격 등 "진짜 정답"을 AI에 입력해야 AI가 더 정확해집니다.
KAMISKorea Agricultural Marketing Information Service
농산물 유통 정보 서비스. 가락시장 등 도매시장의 실시간 경매 가격과 반입량 데이터를 제공합니다.
AGCAutonomous Greenhouse Challenge
네덜란드 와게닝대학교가 주관하는 국제 자율 온실 재배 대회. AI로 원격 온실을 제어하여 최대 수익을 달성하는 것이 목표입니다.
정식Transplanting, 이식
육묘장에서 키운 어린 모종을 온실 본 재배 위치에 옮겨 심는 것. "정식 후 몇 주"가 생육 단계를 나타내는 기준점이 됩니다.
화방Truss, 꽃송이
토마토 줄기에서 꽃이 모여 피는 부분. 화방 하나에 여러 개의 과일이 열립니다. 화방 수가 많을수록 수확량이 늘어납니다.
생장점Growing Point
줄기 맨 꼭대기에서 새 잎과 가지가 나오는 부분. 생장점이 건강해야 식물이 계속 자랍니다. 생장 속도를 확인하는 핵심 관찰 지점입니다.
건물율Dry Matter Content
과일에서 수분을 뺀 고형분의 비율. 건물율 7% 이상이면 맛과 영양이 풍부하다는 뜻입니다. AGC 대회에서는 보너스 점수를 줍니다.
Brix브릭스, 당도
과일의 당도를 나타내는 단위. °Bx로 표시하며, 일반 토마토는 4~6°Bx, 맛이 좋은 토마토는 8°Bx 이상입니다.
건물중Dry Weight / Biomass
식물체를 완전히 건조시킨 무게. 식물이 실제로 광합성으로 만들어낸 유기물의 양을 나타냅니다.
재식밀도Planting Density
단위 면적당 심는 식물 수. AGC 대회 우승팀은 40 pots/m²로 가장 공격적인 밀도를 선택하여 최고 수확량을 달성했습니다.
aT농수산식품유통공사
한국의 농수산물 유통을 관리하는 공공기관. 도매시장 반입량과 가격 데이터를 제공합니다.
ODEOrdinary Differential Equation, 상미분방정식
시간에 따라 변하는 양을 수학적으로 표현하는 방정식. TOMGRO 모델에서 식물 성장량을 시간에 따라 계산하는 데 사용합니다.
WURWageningen University & Research
네덜란드의 세계적인 농업 연구 대학. 온실 재배, 작물 과학 분야의 최고 권위 기관으로, AGC 대회를 주관합니다.
인프라 / 시스템 관련
APIApplication Programming Interface
프로그램끼리 데이터를 주고받는 통로. 기상청 API를 통해 날씨 데이터를 가져오고, KAMIS API로 시세를 조회하는 식입니다.
PLCProgrammable Logic Controller
산업용 자동 제어 장치. AI 서버가 꺼져도 "온도 35도 넘으면 강제 환기" 같은 안전 규칙을 독립적으로 실행합니다.

온실 현장에 설치하는 소형 컴퓨터. 인터넷이 끊겨도 기본 제어를 유지하고, 카메라 영상을 현장에서 바로 분석합니다.
MLOpsMachine Learning Operations
AI 모델을 지속적으로 업데이트하고 관리하는 체계. 새 데이터가 쌓이면 자동으로 재학습하고, 검증 후 배포하는 파이프라인입니다.
Fail-safe페일세이프, 안전장치
AI나 서버에 문제가 생겨도 온실이 안전하게 유지되도록 하는 최후의 안전망. "온도 35도 넘으면 무조건 환기" 같은 규칙이 AI와 독립적으로 작동합니다.
Circuit Breaker서킷 브레이커
과전류 차단기처럼, API 호출 비용이 너무 커지지 않도록 제한하는 장치. GPT-4o Vision 호출을 하루 10장으로 제한하는 것이 예시입니다.
A/B 테스트
같은 조건의 온실 2동을 준비해서, 한 동은 AI가 제어하고 다른 동은 사람이 제어하여 결과를 비교하는 실험 방법입니다.
디지털 트윈Digital Twin
실제 온실을 컴퓨터 안에 똑같이 복제한 가상 모델. 실제로 실험하기 전에 가상 온실에서 "이렇게 하면 어떻게 될까?"를 미리 시뮬레이션합니다.
Jetson OrinNVIDIA 엣지 AI 컴퓨터
NVIDIA가 만든 소형 AI 전용 컴퓨터. 온실 현장에 설치하여 카메라 영상을 실시간으로 분석합니다. 일반 PC보다 작고 전력을 적게 씁니다.
스팟 인스턴스Spot Instance
클라우드(AWS, GCP)에서 여유 서버를 저렴하게 빌리는 방식. 정가의 60~90% 할인되지만, 수시로 회수될 수 있어 AI 학습처럼 중단 가능한 작업에 적합합니다.
JSONJavaScript Object Notation
데이터를 저장하고 전송하는 텍스트 형식. 사람이 읽기 쉬운 구조로, 센서 데이터나 AI 결과를 주고받을 때 많이 사용합니다.
Fallback폴백, 대체 수단
주요 시스템이 고장 났을 때 자동으로 전환되는 백업 방식. 예: 인터넷이 끊기면 엣지 서버가 기본 규칙으로 자동 제어합니다.
이동평균Moving Average
최근 며칠간의 평균을 계산하여 추세를 파악하는 방법. 예: 7일 이동평균 온도. 일시적 변동을 제거하고 전체적인 방향을 봅니다.

PoCProof of Concept, 개념 증명
아이디어가 실제로 작동하는지 소규모로 먼저 테스트하는 것. "AI로 온실을 제어할 수 있을까?"를 간단한 실험으로 먼저 확인합니다.
파이프라인Pipeline
데이터가 수집 → 정제 → 분석 → 결과 출력까지 흐르는 자동화된 경로. 수도관처럼 데이터가 한 방향으로 흘러가며 각 단계에서 처리됩니다.

1-2. 학습 결과 해석

학습 결과 개요: 모델: Random Forest R² (결정계수): 0.89 MAE (평균절대오차): 1.2cm

R² (결정계수) — 모델이 데이터를 얼마나 잘 설명하는지 나타내는 지표

  • 0 = 전혀 설명 못함, 1 = 완벽하게 설명
  • 0.89 = 데이터 변동의 89%를 모델이 설명
  • 일반적으로 0.7 이상이면 유의미, 0.85 이상이면 높은 수준

MAE (평균절대오차) — 예측값과 실제값의 평균 차이

  • 1.2cm = 평균적으로 1.2cm 차이로 예측
  • 주간생장길이가 보통 14~30mm 범위인 점을 감안하면 오차 비율 약 4~8%
33행에서 R² 0.89는 높은 수치이나 과적합 가능성 존재 변수 6개 ÷ 데이터 33행 = 비율 5.5:1 권장 비율: 변수당 최소 10~20행 → 현재 절반 수준

다만 실제 테스트에서 유효한 결과 확인
변수 간 상관관계 자체는 의미 있다고 판단

3-2. 수동 수집 — 작업 일지 표준화

원칙: 했다(1) / 안했다(0)만 기록

  • 적엽 실시 여부 (0/1) — 잎 제거 → 증산/광합성 면적 변화
  • 방제 실시 여부 (0/1) — 농약 살포 → 이후 생육 일시 변동
  • 적과 실시 여부 (0/1) — 과실 솎기 → 남은 과실 비대 촉진
  • 유인 실시 여부 (0/1) — 줄기 정리 → 수광 효율 변화
  • 수분 작업 여부 (0/1) — 착과율에 직접 영향
세부 수치(약제 농도, 적엽 매수 등)는 기록하지 않음
→ 작업자마다 기록 방식이 달라 오히려 노이즈 발생
→ 0/1만 기록하면 오기입 최소화 + 입력 부담 최소화

활용:

센서 데이터 정상인데 생육 수치 이상 → 체크리스트 미완료 항목 확인
→ 해당 작업 실시 알람 발송

AI 방향성

4-1. 우리 데이터 중심

외부 모델(AGC 대회 등)은 변수 선택, 제어 전략 등 참고 자료로 활용
최종 모델은 반드시 GREF 온실 데이터로 직접 학습

품종이 다르고 기후가 다르면 같은 모델도 결과가 달라짐
→ 네덜란드 토마토 최적 모델이 한국 토마토에 맞지 않을 수 있음

활용 가능한 것:

  • 어떤 변수(Feature)가 중요한지 힌트 → AGC 우승팀 분석 참고
  • 단, 실제로 통제 가능하고 측정 가능한 변수만 채택

4-2. 단순한 모델 우선

복잡한 최신 모델(멀티모달 RL + 이미지 딥러닝 등)이 반드시 좋은 결과를 내지 않음

AGC 상위권 모델도 품종/환경이 다르면 성능 보장 안 됨
→ 파인튜닝으로 미세 조정 가능하나 근본적 차이는 해결 안 됨

원칙:

  • Baseline(이동평균, 단순 RF)을 먼저 구축
  • 복잡한 모델이 Baseline을 이기지 못하면 불채택
  • "우리 데이터 안에서 최적의 패턴을 찾는 것"이 핵심 컨셉

4-3. 자동화 전제

모든 데이터는 자동으로 확보 가능한 구조여야 함

수동 측정 의존 시 문제:

  • 측정 간격을 좁히면(주 1회 → 일 1회) 인력이 비례 증가
  • 인력이 부족하면 측정 누락 → 결측치 발생 → 모델 성능 저하
  • 현장이 바쁜 시기(수확기)에 측정 품질 하락

→ 데이터 품질이 현장 상황에 종속되는 구조는 지속 불가

해결:

환경 데이터 → Priva 자동 수집 (이미 가능) 제어 이력 → Priva 자동 기록 (이미 가능) 수동 작업 → 0/1 체크리스트 (최소 부담) 생육 데이터 → 드론/카메라 자동화 추진

4-4. 현재 데이터로 가능한 범위

Priva에 축적된 환경 데이터 기반:

  • 자동 온습도 조절 → Rule-based로 즉시 가능
  • 스크린 자동 개폐 → 현재 데이터 패턴으로 가능

다만 "최적의 환경 값" 도출에는 한계:

현재: 한 가지 제어 패턴의 결과만 축적
필요: 다양한 환경 조절 시도 → 결과 비교 → 최적값 탐색
→ 데이터 양 + 다양성 모두 필요

개발 순서

5-1. 1순위 — 데이터 자동 확보 체계

  • Priva Read 파이프라인 구축 (센서 + 제어 이력)
  • 작업 일지 표준화 (0/1 체크리스트)
  • 파생변수 자동 산출 (VPD, GDD, DLI, DIF)

→ 이 단계 없이는 이후 모든 AI 개발 불가

5-2. 2순위 — 환경 제어 AI

  • Rule-based → MPC → RL 순서로 고도화
  • 현재 Priva 데이터로 자동 온습도/스크린 제어부터 시작
  • RL은 Shadow Mode(백그라운드 기록만)로 병행

5-3. 3순위 — 생육 예측 AI

  • 충분한 데이터 축적 후 RF/LightGBM 본격 학습
  • 수확량 + 품질 등급 예측

→ 출하 시기 최적화 연동

5-4. 4순위 — 비전 AI (이미지 딥러닝)

  • 카메라 기반 병해충 감지 (YOLOv8)
  • 잎/과일 자동 분할 (SAM)
  • 장기적으로 생육 데이터 수동 측정 → 카메라/드론 자동 측정 전환

5-5. 5순위 — 수요/출하 예측

  • 경매 데이터(KAMIS) + 기상 예보 기반
  • 출하 시기/물량 최적화

확장 계획

전제 조건:

GREF에서 자동 데이터 확보 + AI 분석 + 자동화 환경이 완성된 이후

적용 방식

  • 기 학습된 GREF 모델에서 적용 가능한 부분만 반영 (같은 품종이면 생육 패턴 일부 재활용 가능)
  • 적용과 동시에 해당 현장의 환경 데이터 수집 시작
  • 현장별 커스텀 모델 학습 → 품종/기후/시설 차이 반영

핵심 전제

해당 현장에서도 자동 데이터 확보가 가능한 환경이어야 함
수동 측정에 의존하는 현장에는 적용 불가

AI란 무엇인가

인공지능(AI)은 데이터 속 패턴을 찾아내고, 그 패턴을 바탕으로 판단하거나 예측하는 소프트웨어

AI는 로봇이 아님
많은 사람이 AI를 영화 속 로봇으로 떠올리지만, 실제 AI는 눈에 보이지 않는 소프트웨어 스마트폰 안에서, 서버 안에서, 센서 데이터 위에서 조용히 작동. 핵심은 단 하나 — 데이터의 패턴을 찾고, 그 패턴으로 판단하는 것

우리가 이미 매일 사용하고 있는 AI 예시:

  • 번역 파파고, Google 번역 — 문맥을 파악해 자연스럽게 번역
  • 추천 시스템 유튜브, 넷플릭스 — 시청 기록에서 취향 패턴을 학습
  • 음성 인식 시리, 빅스비 — 음성 데이터를 텍스트로 변환
  • 자율주행 테슬라, 웨이모 — 카메라/센서 데이터로 도로 상황 판단
  • 챗봇 ChatGPT, Claude — 텍스트 패턴을 학습해 대화 생성
  • 스팸 필터 이메일 서비스 — 스팸 패턴을 학습해 자동 분류

AI의 역사

1950~1980년대: 규칙 기반 AI
사람이 규칙을 하나하나 직접 코딩하던 시대
  • if-else 로직으로 동작 — 예: "온도 > 30도이면 환기"
  • 대표 기술: 전문가 시스템 (Expert System)
  • 한계: 규칙이 수천 개로 늘어나면 관리가 불가능
1980~2000년대: 통계 기반 AI
데이터에서 수학적 관계를 자동으로 찾기 시작.
  • 선형회귀, SVM 등 통계/수학 모델 등장
  • 대표 기술: SVM, Naive Bayes
  • 한계: 복잡한 비선형 패턴은 포착하지 못함
2000~2010년대: 트리 계열 전성기
정형 데이터(숫자로 된 표)에서 압도적 성능을 보인 시기
  • Random Forest, Gradient Boosting (XGBoost, LightGBM) 등장
  • 정형 데이터에서는 현재도 딥러닝보다 자주 사용됨
  • 해석이 쉽고 빠르며 적은 데이터로도 잘 작동
2010~2020년대: 딥러닝 전성기
이미지, 음성, 텍스트 등 비정형 데이터에서 혁신적 성과를 냄.
  • CNN (이미지), RNN/LSTM (시계열), Transformer 등장
  • ImageNet 대회와 AlphaGo로 대중에게 알려짐
  • GPU 발전이 대규모 신경망 학습을 가능하게 함
2020년~현재: LLM + 멀티모달 시대
하나의 모델이 텍스트, 이미지, 음성을 동시에 처리.
  • GPT, Claude 등 대형 언어 모델(LLM) 등장
  • 텍스트 + 이미지 + 음성을 하나의 모델로 처리
  • 강화학습(RL)은 게임, 로보틱스, 환경 제어에서 계속 발전 중

예시: 토마토 사진 + "병해충 있음" 라벨을 수천 장 학습시키면, 새 사진을 보고 병해충 유무를 판단.

RF LightGBM CNN RNN

Unsupervised Learning
비유: "선생님 없이 스스로 분류"

원리: 정답(라벨) 없이 데이터만 주면, 모델이 비슷한 것끼리 스스로 묶거나 숨겨진 구조를 찾아냄.

예시: 생육 데이터를 넣으면 비슷한 성장 패턴끼리 자동으로 그룹을 만듦.

K-Means DBSCAN

강화학습
Reinforcement Learning
비유: "게임 직접 해보며 실력 키우기"

원리: 모델(에이전트)이 행동을 취하고, 그 결과로 보상이나 패널티를 받으며 더 좋은 행동을 학습.

예시: 가상 온실에서 온도/습도 제어값을 시행착오하며 최적 제어 전략을 찾음.

DQN PPO SAC

지도학습 상세

원리

정답(Y)이 있는 데이터를 주고, X로 Y를 맞추는 연습을 반복함. 예측할 때마다 실제값과 비교해서 오차를 줄여나감.

예시 1 - 트리 계열 (RF)

  • X: 온도 24도, 습도 70%, CO2 800ppm
  • Y: 주간 생장길이 3.2cm
  • 데이터를 보고 "온도 > 25 AND 습도 < 70이면 생장 높음" 같은 규칙을 자동 생성
  • 패턴을 읽고 끝. 가중치 수정 같은 과정 없음

예시 2 - 딥러닝 (CNN)

  • X: 토마토 잎 사진
  • Y: "잿빛곰팡이" 라벨
  • 1회차: 가중치 랜덤 → 예측 틀림 → 오차 계산 → 가중치 수정
  • 2회차: 수정된 가중치로 다시 예측 → 아직 틀림 → 또 수정
  • 수만 회차: 오차가 충분히 줄어들면 학습 완료
  • 새 사진을 보고 병해충 판별 가능

핵심 차이

트리 = 데이터 보고 규칙 추출 (1회성) 딥러닝 = 예측 → 비교 → 수정 반복 (반복 학습)
둘 다 정답(Y)이 필요하다는 점은 동일함.
비지도학습 상세

원리

정답(Y) 없이 X 데이터만으로 숨겨진 패턴이나 그룹을 찾음.

예시 - 생육 패턴 군집

1년치 주간 생장 데이터를 넣으면:

  • 그룹 A: 초반 빠른 성장 → 후반 정체
  • 그룹 B: 꾸준한 성장
  • 그룹 C: 초반 느리다 후반 급성장

각 그룹의 공통점을 분석하면:

  • 그룹 A = 초반 고온 관리 작기
  • 그룹 B = 온도 안정 작기

예시 - 이상 감지

  • 온도/습도/CO2 데이터 군집 분석
  • 대부분 큰 군집 1개 (정상), 떨어진 소수 군집 (이상)
  • 센서 고장, 환기창 오작동 시점 자동 감지
핵심 정답을 구하는 게 아니라, 질문을 발견하는 데 쓰는 도구
대표 모델: K-Means, DBSCAN (RF는 비지도학습이 아님)
강화학습 상세

원리

정답도 없고, 데이터도 미리 주지 않음. 가상 환경에서 직접 행동해보고, 결과에 따라 보상/패널티를 받으며 학습. 보상 기준은 사람이 설계함.

예시 - 온실 환경 제어

  1. 우리 온실 데이터로 가상 시뮬레이터 구성
  2. AI가 가상 온실 안에서 제어값을 시행착오:
    • "난방 10% → 온도 18도, 생장 느림" → -5점
    • "난방 50% → 온도 25도, 가스비 높음" → +3점
    • "난방 30% + CO2 올리기 → 온도 22도, 광합성 최적" → +10점
  3. 수백만 번 반복 → 최적 제어 전략 완성

현실 6개월 재배 = 컴퓨터에서 3시간으로 압축됨.

시뮬레이터 역할

  • 우리 데이터 → 시뮬레이터(가상 온실)의 물리 법칙 구성
  • AI 행동 → 시뮬레이터 안에서 자율 탐험
  • 보상 기준 → 우리가 설계
Deep RL 딥러닝(뇌) + 강화학습(경험으로 훈련)을 결합한 것

모델 종류별 상세 설명

트리 계열 (Random Forest, LightGBM)

원리

데이터를 보고 if-else 규칙을 자동으로 생성하여 분류하거나 예측함. 사람이 규칙을 짜는 것이 아니라, 데이터에서 가장 효과적인 분기 조건을 알아서 찾아냄.

온도 > 25 AND 습도 < 70% → 수확량 높음

장점

  • 결과를 해석하기 쉬움 (어떤 변수가 중요한지 알 수 있음)
  • 학습 속도가 빠름
  • 데이터가 적어도 잘 작동함

단점

  • 이미지, 텍스트 같은 비정형 데이터는 처리 불가
  • 전이학습 불가 (학습한 지식을 다른 문제에 재활용할 수 없음)
비유 수치 패턴 읽기 전문가 — 숫자로 된 표를 보고 빠르게 규칙을 찾아내지만, 사진이나 글을 읽는 능력은 없음.
딥러닝 (Neural Network)

뉴런 하나의 구조

딥러닝의 가장 작은 단위인 뉴런은 아래와 같이 동작:

입력 × 가중치(w) + 편향(b) → 활성화 함수 → 출력

이런 뉴런이 수백~수억 개 연결되어 복잡한 패턴을 학습.

학습 과정 (역전파)

  1. 예측: 입력 데이터가 신경망을 통과하여 출력값 생성
  2. 오차 계산: 예측값과 실제 정답의 차이를 계산
  3. 역전파: 오차를 뒤로 전달하면서 각 가중치를 수정
  4. 반복: 수만~수십만 번 반복하면 오차가 점점 줄어듦

CNN (합성곱 신경망) — 이미지 처리 전문

작은 필터(커널)로 이미지를 훑으며 특징을 추출함. 층이 깊어질수록 더 복잡한 특징을 인식함.

가장자리 인식 → 패턴 인식 → 물체 부위 인식 → 물체 전체 인식

대표 모델: YOLOv8, SAM, CLIP

RNN / LSTM (순환 신경망) — 시계열 데이터 전문

순서가 있는 데이터(시계열)를 처리하는 데 특화된 구조 이전 시점의 정보를 기억하면서 다음 시점을 예측함.

사용 예: 온도, 습도, CO2 농도의 시간별 변화 예측

Transformer — 문맥 파악, 장거리 패턴

Attention(주의 집중) 메커니즘을 사용하여 데이터 전체에서 중요한 부분에 집중함. 시계열이든 텍스트든, 먼 거리에 있는 데이터 간의 관계도 잘 파악함.

대표 모델: GPT, Claude, TimesFM

MLP (다층 퍼셉트론) — 가장 기본적인 딥러닝

뉴런을 여러 층으로 쌓은 가장 단순한 형태의 딥러닝 정형 데이터에 사용되며, 강화학습의 Policy Network로도 사용됨.

전이학습은 왜 되는가?

핵심 원리 ImageNet의 1,400만 장 이미지로 학습한 가중치(선, 질감, 모양 인식 능력)를 재활용함. 이 가중치를 토마토 병해 사진 1,000장으로 Fine-tuning(미세 조정)하면, 처음부터 학습할 때 수만 장이 필요한 것을 1/10~1/100 수준으로 줄일 수 있음.
Random Forest는 전이가 안 되는 이유 RF의 지식은 트리 구조 자체에 저장됨. 새로운 데이터가 들어오면 기존 트리는 재활용이 불가능하고, 처음부터 트리를 다시 생성해야 함.
강화학습 (Reinforcement Learning)

핵심 구조

State (상태) → Action (행동) → Reward (보상) → 반복

특징

  • 정답이 없음. 대신 보상 함수로 "좋다/나쁘다"를 평가함
  • 가상 환경(시뮬레이터)에서 수백만 번의 시행착오를 거침
  • 보상 함수는 사람이 설계함 (예: "수확량 많으면 +1, 에너지 과다 사용하면 -0.5")

Deep RL (딥러닝 + 강화학습)

딥러닝 신경망을 강화학습의 의사결정 엔진으로 사용하는 방식 대표 알고리즘으로 SAC, PPO가 있음.

비유 딥러닝 = 뇌, 강화학습 = 경험으로 뇌를 훈련시키는 방식. 뇌(신경망)가 더 크고 좋을수록 복잡한 문제도 잘 풀 수 있음.
생성 모델 (Generative Models)

GAN (적대적 생성 신경망)

두 신경망이 경쟁하며 발전함. Generator(생성자)는 가짜 데이터를 만들고, Discriminator(판별자)는 진짜와 가짜를 구분함. 둘이 서로 경쟁하면서 생성 품질이 점점 좋아짐.

비유 위조범(Generator) vs 감정관(Discriminator)의 경쟁. 위조범이 점점 정교해지고, 감정관도 점점 까다로워짐

Diffusion (확산 모델)

이미지에 노이즈를 점점 추가한 뒤, 그 노이즈를 다시 제거하는 과정을 학습. 학습이 완료되면 순수한 노이즈에서 새로운 이미지를 생성할 수 있음.

대표 모델: Stable Diffusion, DALL-E

LLM (대형 언어 모델)

"다음 단어 예측"을 수조 개의 텍스트 데이터로 반복 학습. 그 결과 문맥을 이해하고, 질문에 답하고, 글을 생성하는 능력을 갖추게 됨.

Y값 설계 주의점 (다중 출력)

작물 생육 지표(Y)가 여러 개인 경우

주간 생장길이, 줄기 두께, 화방 수 등 Y가 여러 개일 수 있음.

처리 방법: Y 하나당 모델 하나

  • 모델 A: X(센서값) → Y1(주간 생장길이)
  • 모델 B: X(센서값) → Y2(줄기 두께)

주의사항

같은 시점의 Y값을 다른 모델의 X로 쓰면 안 됨 이를 데이터 누수(Data Leakage)라고 함. 정확도가 높게 나오지만 실전에서는 사용할 수 없음. 과거 시점의 Y는 X로 사용 가능 (시간 순서가 맞으면 OK).
작업 일지

센서 데이터만으로는 "왜 이런 패턴이 나왔는지" 알 수 없음.

수치화 방법

작업 여부를 0과 1로 기록함.

활용

센서 정상 + 생육 이상 감지 → 체크리스트 알람
